# MoKnow 发布流程

本文档记录本地发布检查、CI Release 工作流和仍需外部账号/证书完成的发布事项。

## 本地检查命令

| 命令 | 作用 | 适用场景 |
|---|---|---|
| `npm run release:check` | 校验 `package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` 版本一致，检查 `CHANGELOG.md`、Release workflow、Tauri bundle 和图标配置 | 日常发布前快速自检 |
| `npm run release:check -- --strict-external` | 在静态检查基础上，强制要求 AI 联调、updater、签名、公证和分发 URL 相关环境变量已配置 | 正式 tag / Release 前最终检查 |
| `npm run release:updater-config` | 从 `MOKNOW_UPDATER_PUBKEY`、`MOKNOW_UPDATER_ENDPOINT` 或 `MOKNOW_RELEASE_DOWNLOAD_BASE_URL` 生成被忽略的 `src-tauri/tauri.updater.conf.json` | 签名 updater 构建前准备 |
| `npm run release:artifacts` | 检查当前平台 Tauri bundle 产物是否存在，并提示 updater `.sig` 签名文件状态 | 本机或 CI 构建后检查安装包 |
| `npm run release:downloads` | 扫描下载后的 GitHub Actions artifacts 目录，生成 `release/download-verification.json` / `.md`，可写回 `项目文档/发布产物验证记录.md` | 下载 artifacts 后做完整性验证 |
| `npm run release:install-smoke` | 检查 `.app`、DMG、Windows / Linux 安装器入口，并生成安装打开读写冒烟验证清单 | 本机或下载 artifacts 后验证安装包入口 |
| `npm run release:install-manual` | 记录人工安装、打开、仓库读写、保存和重启恢复验收结果；`--result passed` 必须配合 `--confirm-all` 或逐项确认 flag | 实机安装验证完成后补充人工证据 |
| `npm run release:signing` | 检查 macOS codesign / Gatekeeper / stapler、Windows Authenticode 和 Linux 分发签名策略，并生成签名验证记录 | 签名、公证或下载产物后验证 |
| `npm run release:aggregate-evidence` | 扫描下载后的三平台 artifacts，合并各平台内置的 `install-smoke.json` 和 `signing-verification.json` 为顶层报告 | 远端矩阵构建完成后的全平台证据聚合 |
| `npm run release:workflow-validate` | 解析 Release / Release Dry Run workflow YAML，结构化检查三平台矩阵、build / verify job、artifact 上传下载、AI 证据、聚合验证和正式 Release 严格签名分发门禁；远端 verify job 会上传 `workflow-validation.json` / `.md` | 提交 workflow 前做结构验证 |
| `npm run release:ci-preflight` | 检查 GitHub CLI 登录、workflow 本地内容、git 跟踪状态和远端 workflow 是否可触发，并写入 `项目文档/发布CI预检记录.md` | 触发远端 dry-run 前 |
| `npm run release:remote-status` | 读取远端 Release / Release Dry Run workflow、最近 runs、artifacts 和 GitHub Release 状态，生成 `release/remote-status.json` / `.md`，可写回 `项目文档/发布远端状态记录.md`；`--strict` 要求目标 workflow 存在且最近成功 run 含三平台和 verification artifacts | 远端 dry-run / tag run 后复核 CI 和 artifacts 状态 |
| `npm run release:metadata` | 基于 Tauri bundle 生成 `release/downloads.json`、`release/latest.json` 和 `release/homebrew/moknow.rb` | 发布分发元数据准备 |
| `npm run release:distribution` | 验证 `downloads.json`、`latest.json`、Homebrew cask、下载 URL、updater endpoint、官网 URL 和 Homebrew tap 配置；`--strict --require-reachable` 可要求真实 URL 可达 | 官网 / Homebrew / 自动更新实发前验证 |
| `npm run release:secrets` | 使用 GitHub CLI 审计仓库 Actions secrets 名称是否已配置，只记录名称和更新时间，不读取 secret 值 | 正式 Release workflow 外部凭据审计 |
| `npm run release:secrets:sync` | 从当前 shell 环境变量生成 GitHub Actions secrets 同步预览；加 `--apply --verify` 后才会写入远端并重新审计 | 外部凭据到位后批量写入 GitHub secrets |
| `npm run release:readiness` | 生成 AI、updater、签名、公证、下载 URL、Homebrew tap 的脱敏外部配置清单；`--strict` 可在缺项时失败 | 正式发布前外部配置审计 |
| `npm run release:handoff` | 生成外部闭环交接清单、GitHub secrets 设置命令、本机环境变量模板和最终验收命令 | 对项目进度 3 个外部未闭环项做交接和配置准备 |
| `npm run release:closure` | 串行运行入库、AI 真实联调、远端 CI、三平台下载/安装、secrets、readiness、签名、公证、metadata、分发和最终审计严格门禁，生成 `release/closure-gate.json` / `.md`，可写回 `项目文档/发布外部闭环总门禁记录.md`；默认只出报告，`--strict` 会在任何失败项存在时返回非零 | 对项目进度 3 个外部未闭环项做一键总验收 |
| `npm run release:final-audit` | 汇总 AI 真实联调、远端三平台 CI、下载/安装、签名公证和分发元数据证据，生成 `release/final-progress-audit.json` / `.md`，可写回 `项目文档/项目进度.md` | 对照项目进度未完成项做最终证据审计 |
| `npm run release:tracking` | 检查发布闭环所需 workflow、脚本、Makefile 和项目文档是否存在、是否被 `.gitignore` 忽略、是否已纳入 git；`--strict` 要求全部已跟踪 | 提交推送前防止漏文件 |
| `npm run release:submit-prep` | 一键运行提交安全检查、提交计划、提交预演、推送准备和 CI 预检报告，生成 `项目文档/发布提交准备总览.md`；不执行真实 `git add` / commit / push | 提交前总入口 |
| `npm run release:submission-safety` | 扫描发布闭环 pathspec / 必需文件，确认不包含密钥、证书、私钥、生成产物或额外路径，生成 `项目文档/发布提交安全检查记录.md` | `git add` 前做安全检查 |
| `npm run release:submission-plan` | 生成发布闭环必需文件清单、NUL 分隔 pathspec 文件 `release/submission-pathspec.txt` 和 `项目文档/发布提交入库计划.md`；不执行 `git add` / commit / push | 提交前安全纳入中文路径和新增脚本 |
| `npm run release:submission-preview` | 使用临时 index / object 目录按 pathspec 预演提交内容，生成 tree hash、diff 统计和 `项目文档/发布提交预演记录.md`；不执行真实 `git add` / commit / push | 提交前确认会纳入哪些文件 |
| `npm run release:push-readiness` | 读取当前分支、upstream、提交计划、GitHub CLI 登录和远端 workflow 状态，生成 `项目文档/发布推送准备记录.md`；不执行 `git add` / commit / push | 推送 workflow 前确认本地清单可入库、远端阻断清晰 |
| `npm run release:dry-run` | 先执行 workflow 结构验证和严格 CI 预检，再使用 GitHub CLI 触发 Release Dry Run workflow，等待完成、刷新 dry-run 远端状态、下载 artifacts，并执行下载完整性、安装冒烟、签名验证和最终进度审计 | 正式 tag 前远端三平台演练 |
| `npm run release:verify` | 执行发布静态检查、前端测试和前端构建 | 打 tag 前的基础质量门禁 |
| `npm run release:local` | 执行发布静态检查、前端测试、前端构建、本机 Tauri 构建和当前平台产物检查 | 本机有完整 Tauri 构建环境时使用 |

## 打 Tag 流程

1. 更新 `package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` 为同一版本号。
2. 将 `CHANGELOG.md` 中 `[Unreleased]` 内容整理到 `## [x.y.z]` 小节。
3. 执行 `npm run release:handoff -- --write-doc`，更新 `项目文档/发布外部闭环交接清单.md` 和环境变量模板，确认真实 Provider、GitHub secrets、签名、公证、updater、Homebrew / 官网分发所需值已有人负责配置。
4. 在当前 shell 配置好外部变量后执行 `npm run release:secrets:sync -- --write-doc` 预览；确认报告无误后执行 `npm run release:secrets:sync -- --apply --verify --write-doc` 写入 GitHub Actions secrets。
5. 执行 `npm run release:workflow-validate -- --strict --write-doc` 和 `npm run release:submit-prep -- --write-doc`，生成提交前 workflow 结构验证、提交安全检查、NUL 分隔 pathspec、提交预演、推送准备记录、CI 预检和入库清单；随后执行 `git add --pathspec-from-file=release/submission-pathspec.txt --pathspec-file-nul`，再执行 `npm run release:tracking -- --strict --write-doc`，确认 workflow、脚本和项目文档都已纳入 git。
6. 执行 `npm run release:verify`。
7. 在有 Tauri 构建环境的机器上执行 `npm run release:local`。
8. 执行 `npm run release:dry-run -- --write-doc`。该命令会先执行 `release:workflow-validate -- --strict` 和 `release:ci-preflight -- --strict`，确认 workflow 结构正确、已提交推送且远端可触发；通过后再通过 GitHub CLI 触发 `.github/workflows/release-dry-run.yml`，让 macOS、Windows、Linux runner 构建 bundle、运行 `ai:e2e:auto`、`release:artifacts`、`release:install-smoke`、`release:signing` 和 `release:final-audit`，上传 `moknow-dry-run-*` artifacts、AI 联调记录、安装冒烟报告、签名验证报告和最终进度审计报告。矩阵结束后 workflow 的 `verify` job 会下载三平台 artifacts，执行 `release:workflow-validate`、`ai:e2e:auto`、`release:downloads`、`release:aggregate-evidence` 和 `release:final-audit`，形成本次 dry-run 的全平台总验证报告；本地自动化等待完成后会执行 `release:remote-status -- --mode dry-run --strict`，再下载 artifacts 并执行同一套聚合步骤。也可在 GitHub Actions 页面手动触发。
9. 执行 `npm run release:remote-status -- --strict --write-doc`，确认远端 dry-run workflow、最近成功 run 和三平台 / verification artifacts 均可读取。
10. dry-run artifacts、人工安装记录、签名公证和分发配置都到位后，执行 `npm run release:closure -- --strict --write-doc`；该总门禁应全部通过，才可把 `项目文档/项目进度.md` 中 3 个外部闭环项改为完成。
11. 提交变更并创建 `vX.Y.Z` tag。
12. 推送 tag 后，`.github/workflows/release.yml` 会先用 `MOKNOW_UPDATER_PUBKEY` 和 Release 下载 URL 生成 `src-tauri/tauri.updater.conf.json`，再用 `--config` 构建 macOS、Windows、Linux bundle，并创建 GitHub 草稿 Release。
13. CI 会运行 `npm run ai:e2e:auto -- --write-doc`、`npm run release:artifacts -- --require-updater-signatures`、`npm run release:install-smoke`、`npm run release:signing -- --require-signed --require-notarized`、`npm run release:metadata -- --require-base-url --require-updater-signatures`、`npm run release:distribution -- --strict` 和 `npm run release:final-audit`，并把三平台安装包、updater bundle、`.sig` 文件、AI 联调记录、安装冒烟报告、签名验证报告、分发验证报告、最终进度审计报告、`latest.json`、下载清单和 Homebrew cask 上传为 GitHub Actions artifacts。矩阵结束后的 `verify` job 会下载所有平台 artifacts，执行 `release:downloads -- --require-metadata --require-updater-signatures`、`release:distribution -- --strict`、`release:aggregate-evidence` 和 `release:final-audit`，再把总验证报告上传到 Actions artifacts 和 Draft Release。
14. CI 会把 `release/downloads.json`、`release/latest.json` 和 macOS job 生成的 `release/homebrew/moknow.rb` 上传到 GitHub Draft Release。
15. 下载三平台 artifacts / Draft Release 产物，执行 `npm run release:remote-status -- --strict --write-doc` 和 `npm run release:signing -- --artifact-root release/downloaded-artifacts --platform all --require-signed --require-notarized --write-doc`，再完成安装和打开验证。人工安装打开读写通过后执行 `npm run release:install-manual -- --result passed --confirm-all --artifact-root release/downloaded-artifacts --platform all --write-doc`，随后重新执行 `npm run release:install-smoke -- --artifact-root release/downloaded-artifacts --platform all --write-doc`，把结果记录到 `项目文档/发布远端状态记录.md`、`项目文档/发布产物验证记录.md`、`项目文档/发布安装人工验收记录.md` 和 `项目文档/发布签名验证记录.md` 后发布 Release。

## 外部依赖项

| 项目 | 当前状态 | 说明 |
|---|---|---|
| AI 真实联调 | 待实机运行 | 需要 `AI_E2E_ENDPOINT`、`AI_E2E_MODEL`、`AI_E2E_API_KEY`，或本地 OpenAI-compatible 服务配合 `--allow-no-key`；Release / Release Dry Run workflow 已在配置 `AI_E2E_*` secrets 时自动执行 `ai:e2e:auto`。 |
| GitHub Actions secrets | 待配置 | 执行 `npm run release:secrets:sync -- --write-doc` 可预览本机环境变量到 GitHub secrets 的同步计划；加 `--apply --verify` 后写入远端并重新审计。执行 `npm run release:secrets -- --strict --write-doc` 可检查 updater、macOS、Windows 和 Homebrew 发布所需 secret 名称是否存在。 |
| macOS 签名 | 待配置 | 需要 `APPLE_CERTIFICATE`、`APPLE_CERTIFICATE_PASSWORD`，可选 `APPLE_SIGNING_IDENTITY`。 |
| macOS 公证 | 待配置 | Apple ID 模式需要 `APPLE_ID`、`APPLE_PASSWORD`、`APPLE_TEAM_ID`；App Store Connect API 模式需要 `APPLE_API_KEY`、`APPLE_API_ISSUER` 和私钥文件路径。 |
| Windows code signing | 待配置 | 需要 `WINDOWS_CERTIFICATE`、`WINDOWS_CERTIFICATE_PASSWORD`，或按证书/云签名服务配置 `TAURI_WINDOWS_SIGNTOOL_PATH` / 自定义签名命令。 |
| 自动更新 | 应用内入口和配置生成已接入，待真实签名和端点实跑 | 命令面板“检查应用更新”会在 Tauri 桌面环境调用 updater；`release:updater-config` 会生成包含 `createUpdaterArtifacts`、公钥和 endpoint 的临时 Tauri 配置；正式实发仍需要 `TAURI_SIGNING_PRIVATE_KEY`、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`、`MOKNOW_UPDATER_PUBKEY`、HTTPS 更新端点和发布产物 `.sig`。 |
| Homebrew / 官网分发 | 元数据生成与 readiness 检查已接入，待实发 | `npm run release:metadata` 可生成下载清单和 Homebrew cask；`npm run release:readiness` 会检查 `MOKNOW_HOMEBREW_TAP`、`MOKNOW_RELEASE_DOWNLOAD_BASE_URL`、`MOKNOW_HOMEPAGE_URL`；正式分发仍需要 GitHub Release 下载 URL、Homebrew tap / 官网页面实发。 |

## AI 外部模型联调

1. 优先执行 `npm run ai:e2e:auto -- --write-doc`。该命令会探测 `AI_E2E_*` / `OPENAI_*` 环境变量、本机 Ollama 和 LM Studio；发现可用真实 Provider 时会直接执行 E2E，并生成 `release/ai-e2e.json`。
2. 如需显式外部服务验收，在本机或 CI secret 中配置 `AI_E2E_ENDPOINT`、`AI_E2E_MODEL`、`AI_E2E_API_KEY`。
3. 执行 `npm run ai:e2e:preflight -- --strict --write-doc`，确认 endpoint、model、API Key 和 HTTPS / 本地服务规则均满足。
4. 无真实 Key 时可先执行 `npm run ai:e2e:mock -- --write-doc`，确认脚本可完成鉴权、非流式响应解析和 SSE 流式解析；该结果不等同于真实模型验收。
5. 执行 `npm run ai:e2e`；需要同时验证 SSE 时执行 `npm run ai:e2e -- --stream`。
6. 确认 `项目文档/AI外部模型联调记录.md` 已生成最近记录，且没有写入 API Key。
7. 执行 `npm run release:check -- --strict-external`，确认 AI 外部联调环境不再缺失。

## 产物下载验证

1. 推送 `vX.Y.Z` tag 触发 Release workflow。
2. 在 GitHub Actions 中下载 `moknow-macOS-*`、`moknow-Windows-*`、`moknow-Linux-*` artifacts。
3. 先执行 `npm run release:install-smoke -- --artifact-root release/downloaded-artifacts --platform all --write-doc`，检查安装包入口并写入自动冒烟验证区。
4. 对每个平台产物执行安装、打开、创建/打开仓库和保存 Markdown 的实机冒烟验证。
5. 人工验证完成后执行 `npm run release:install-manual -- --result passed --confirm-all --artifact-root release/downloaded-artifacts --platform all --write-doc`，生成 `项目文档/发布安装人工验收记录.md`；之后再次执行 `npm run release:install-smoke -- --artifact-root release/downloaded-artifacts --platform all --write-doc`，让安装冒烟报告读取持久化人工结果。
6. 将下载地址、校验结果和安装验证结论写入 `项目文档/发布产物验证记录.md`。
7. 正式 tag 前可执行 `npm run release:dry-run -- --write-doc` 自动触发 Release Dry Run workflow、等待完成、下载 `moknow-dry-run-*` artifacts 并运行完整性验证。
8. 若手动下载 artifacts，则解压到 `release/downloaded-artifacts` 后执行 `npm run release:downloads -- --write-doc`，自动生成完整性验证报告并写回 `项目文档/发布产物验证记录.md`。

## 远端 CI 预检

1. 执行 `npm run release:ci-preflight -- --write-doc` 记录 GitHub CLI、远端 workflow 和本地 workflow 状态。
2. 当前记录显示 GitHub CLI 已登录且本地 workflow 内容齐全，但 `.github/workflows/release-dry-run.yml` / `release.yml` 还未纳入 git 索引，远端 `release-dry-run.yml` 返回 404。
3. 执行 `npm run release:submit-prep -- --write-doc` 生成提交安全检查、`release/submission-pathspec.txt`、提交预演与推送准备记录，再用 `git add --pathspec-from-file=release/submission-pathspec.txt --pathspec-file-nul` 纳入 workflow、脚本和项目文档；之后执行 `npm run release:tracking -- --strict --write-doc` 确认入库。
4. 提交并推送 workflow 和脚本后，执行 `npm run release:dry-run -- --write-doc`；命令会自动调用严格预检。仅在排查远端 workflow run/list 行为时使用 `npm run release:dry-run -- --skip-preflight`。

## 分发元数据

1. 本地可执行 `npm run release:metadata` 生成 `release/downloads.json`、`release/latest.json` 和 `release/homebrew/moknow.rb`。
2. 正式发布时配置 `MOKNOW_RELEASE_DOWNLOAD_BASE_URL=https://github.com/{owner}/{repo}/releases/download/vX.Y.Z` 和 `MOKNOW_HOMEPAGE_URL=https://github.com/{owner}/{repo}`。
3. 配置 `MOKNOW_HOMEBREW_TAP=owner/homebrew-tap`，用于 readiness 报告记录正式 cask 发布目标。
4. 构建 updater 包前配置 `MOKNOW_UPDATER_PUBKEY` 和 `TAURI_SIGNING_PRIVATE_KEY`，执行 `npm run release:updater-config` 后用 `tauri build --config src-tauri/tauri.updater.conf.json` 构建。
5. 若 updater `.sig` 已生成，`latest.json` 会写入对应平台的更新 URL 和签名。
6. 将 `release/homebrew/moknow.rb` 复制到 Homebrew tap 后，确认 `url`、`sha256` 和 `homepage` 均指向真实发布资产与项目主页。
7. 安装已配置 updater endpoint 的桌面包后，可从命令面板执行“检查应用更新”验证应用内更新检查链路。
8. 执行 `npm run release:distribution -- --strict --require-reachable --write-doc`，确认下载资产、updater endpoint、Homebrew cask URL 和官网 / 项目主页均为真实 HTTPS 且可达。
9. 执行 `npm run release:secrets -- --strict --write-doc`，确认 GitHub Actions secrets 已配置；报告不会读取或记录 secret 值。

## 签名与公证验证

1. 当前本机未配置 Developer ID / notarization，`npm run release:signing -- --write-doc` 会记录 macOS app 为 ad-hoc/linker-signed、DMG 未签名的证据。
2. 正式发布时配置证书并构建后，执行 `npm run release:signing -- --require-signed --require-notarized --write-doc`。
3. Windows 产物需在 Windows runner 或本机执行同一命令，脚本会调用 `Get-AuthenticodeSignature` 验证 Authenticode 状态。
4. Linux 产物至少保留 `downloads.json` SHA-256；如通过包仓库分发，再补充 GPG / repo 签名验证记录。
